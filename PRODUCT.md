# Product

## Register

product

## Users

ECU and software engineers use a browser on Windows to request diagnostic certificates and sign software digests or text. PKI and DSS have independent tool accounts. Administrators maintain users, template mappings, DSS project access and audit records.

## Purpose

Provide focused workflows over existing supplier APIs. PKI users choose a configured tertiary template and environment, then supply certificate details or a CSR. DSS users sign a digest or UTF-8 text using a key assigned to their project. Supplier changes are outside scope. Records are retained for one year.

PKI accounts are not restricted by project. The tool reads identifiers from uploaded CSRs; generated requests ask for the fields required by the selected role. DSS signs the decoded digest bytes or UTF-8 text with Ed25519 and returns a detached signature. It does not upload software packages. Connections and existing supplier objects are mapped by administrators; incomplete access materials or unconfirmed protocol rules block real operations. A local demonstration is never presented as a verified supplier result.

## Experience

English and Arial throughout. A blue ZF identity with the restraint of a professional engineering tool: compact headings, clear labels, balanced layouts and useful copy. The homepage offers two equal tool choices. Login is centered. Working screens prioritize inputs and results.

## Principles

1. Show the next action clearly and keep background explanation brief.
2. Keep module and project access visible without exposing API details to ordinary users.
3. Make results easy to copy or download and records easy to inspect.
4. Support mobile, keyboard use, legible contrast and reduced motion.
5. Preserve supplier API capabilities and existing authorization behavior.

## Avoid

Large promotional text, unbalanced image/form splits, fake logos, decorative dashboards, unnecessary badges, excessive motion and supplier implementation details in ordinary engineer workflows.
